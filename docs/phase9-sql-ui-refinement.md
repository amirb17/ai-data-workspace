# Phase 9 SQL Analytics UI refinement

The SQL workspace now opens in Visual Builder, with a searchable data catalog, clause navigation, authoritative generated SQL, an adjacent CodeMirror editor, searchable saved-query/history drawers, and bounded results/charts. No commit was made and Phase 10 was not started.

1. **Existing UI problems.** SQL opened first; Builder was a single undifferentiated form with one aggregate, generated SQL appeared only after leaving Builder, schema discovery was a dropdown, saved/history controls were collapsed together, replacements used native confirmation, results had no search/index, and Details exposed internal source version IDs.
2. **Files changed for this refinement.** See the file inventory below. The earlier uncommitted Phase 9 routing, migration, sandbox, loader, policy, persistence and service implementation were preserved. No dependency or migration was added.
3. **Page hierarchy.** Workspace breadcrumb/status and Saved Queries / Query History / New Query actions; left Data Catalog on desktop; Visual Builder / SQL Editor authoring surface; Results / Chart / Query Details underneath. Existing navy application navigation remains intact.
4. **Builder experience.** Default, directly discoverable authoring mode with typed selections and optional steps. Every generated query uses the existing backend SQLGlot compiler and authoritative SQL validator. No query executes while configuring controls.
5. **SQL Editor.** Existing CodeMirror retained, smaller usable editing surface, explicit DuckDB Analytics dialect, Format/Validate controls, prominent Run, shortcuts, metadata examples and quick help. Qualified dataset completion now shows compact column/type/role choices without duplicate bare fields or unrelated keywords.
6. **Clause navigation.** SELECT, FROM, JOIN, WHERE, GROUP BY, HAVING, ORDER BY, LIMIT can be visited in any order. Clauses wrap on larger screens and scroll internally on mobile.
7. **SELECT.** Up to 30 removable selections, per-field type-aware aggregation, COUNT(*) choice, explicit aggregate output names, and move-up/down controls. Multiple aggregates are now supported through an additive typed contract. Duplicate output names, unsupported types, missing fields and missing grouping are rejected by the backend.
8. **FROM.** Searchable dataset selection; current sources can be chosen, stale sources remain visible and disabled with the real catalog reason. Changing the source clears selections, filters, grouping, sorting, lookup and displayed results.
9. **JOIN.** Only current confirmed child-to-parent relationships whose parent remains current appear. A single LEFT lookup uses metadata-derived keys/direction/cardinality. No arbitrary keys or candidate joins. Empty guidance appears when no relationship is available.
10. **WHERE.** Up to four AND filters with compatible operators, text/numeric/date/timestamp/boolean controls, correctly typed BETWEEN endpoints, IS NULL and IS NOT NULL. Text categories use literal inputs because the catalog does not provide authorized value enumerations. Sensitive fields are excluded from choices.
11. **GROUP BY/HAVING.** Up to three grouping fields. Non-aggregated output fields are suggested visibly and added only by an explicit action. HAVING is a guidance step: use validated SQL Editor queries because the typed V1 Builder has no HAVING representation.
12. **ORDER BY/LIMIT.** One sort over selected output names only; ascending/descending. Presets 50/100/250/500 are filtered by the backend ceiling; custom limits are positive integers clamped to that ceiling. Additional sorts remain available in SQL Editor.
13. **Dropdown system.** SearchSelect is reused for both long searchable lists and short choices. All popovers portal to the body above dialogs, clamp/flip inside the viewport, show selected state and disabled reasons, close outside/on Escape, and handle keyboard navigation. Short controls focus their actual listbox; searchable controls expose the active descendant on the search input. Escape/Tab are contained so a dropdown does not also close its enclosing drawer.
14. **Dependent behavior.** Dataset changes reset dependent fields. Column changes reset incompatible aggregation/aliases and sorting. Catalog updates reconcile missing/sensitive fields, changed types, invalid filters/groups/sorts and stale relationships. New execution results remount chart state; chart-type changes clear axes. Aborted/out-of-order preview responses cannot replace current SQL.
15. **Schema browser.** Dataset/column search, dataset names/current status/column counts, authoritative row counts only, Columns/Details/Relationships sections, reliable key/dimension/measure/time/other groups and relationship indicators. Internal IDs/version hashes/paths are not rendered. Technical workspace-scoped aliases necessarily remain in actual SQL and SQL completions.
16. **Generated SQL.** Debounced calls to the existing Builder endpoint update a bounded SQL preview. Copy and Open in SQL Editor are explicit actions. Incomplete/invalid configuration clears executable preview immediately. Requests are aborted on input/workspace changes or unmount. There is no automatic execution.
17. **Builder to SQL transition.** Generated SQL is copied into CodeMirror. The unchanged generated text can return to the retained Builder state. Any manually divergent or independently opened SQL is conservatively guarded; Keep SQL Editor or Reset Builder is explicit. No general reverse parser is claimed.
18. **Result grid.** Local search over returned rows, row index, sticky headers, subtle alternating rows, exact NULL/string/decimal/large-integer display and copy, internal horizontal scrolling, bounded 50-row paging and local sorting. Returned row count, duration, freshness, success/failure chip and truncation remain visible. No invented KPI cards.
19. **Charts.** Returned data only. Bar X choices exclude numeric/boolean fields; line X choices require date/time fields with at least two valid distinct points. Duplicate/null X values and results over 100 rows are disabled with reasons. Y choices require actual finite numeric values; exact decimal/large-integer strings remain in the table. Chart-type changes clear axes, and unsupported line choices are disabled. Renderer and controls share one compatibility model.
20. **Query Details.** Status, execution time, duration, returned rows, named sources, freshness, named confirmed lookup direction and DuckDB engine/version. Source state/Gold IDs were removed from display. Ad hoc SQL remains clearly distinguished from a trusted metric.
21. **Saved Queries.** Searchable drawer with name/modified date/description and Open/Rename/Duplicate/Delete actions. Delete uses the existing confirmation and optimistic version API. Rename now preserves saved SQL independently of an unsaved authoring draft; this state defect was caught and fixed during review.
22. **Query History.** Searchable drawer, status filter, SQL snippet, rows, duration and time; Open SQL never executes. Historical rows are not retained and the UI explains that rerunning is required for current data.
23. **New Query.** Starts a clean Builder session. Unsaved work produces one focus-contained dialog with Keep editing and Discard and start new query. Clean saved queries do not need an interruption. SQL recovery text is also protected.
24. **First-time state.** Explore your trusted data; Builder and SQL entry actions; starter SQL generated from real current metadata. No global hardcoded business examples, fake rows or fake approvals.
25. **Mobile/tablet.** Data Catalog drawer below desktop, internally scrolling clause controls, stacked selection/filter controls, usable editor, sticky mobile authoring footer, bounded grid/chart widths. At 390px the page was 375px wide (remaining width is the scrollbar), and the Run button was visibly within the viewport; at 768px the page was 753px wide. Neither had page overflow.
26. **Accessibility.** Labeled controls, semantic fieldsets, current clause state, selected authoring modes, roving result tabs, live status/error messages, accessible popup/listbox state, keyboard selection, focus containment/restoration for drawers and confirmation dialogs, Escape containment, comfortable minimum button heights. This is focused engineering/browser verification, not a formal screen-reader audit.
27. **Tests.** 87 focused compiler/SQL safety tests passed. Fresh RUN_DB_TESTS=1 SQL module: 7 passed, no skips, including actual multi-selection compile → execution → persisted history → API read and existing ownership/freshness/resource protections. The disposable real-HTTP fixture also completed successfully and cleaned up its schema (1 passed). All 25 frontend .cjs scripts passed, including new workspace interaction coverage and expanded selection/chart tests. The expensive full backend suite was not repeated for this UI-scoped request; these are fresh focused results, not historical full-suite claims.
28. **Lint/build.** Frontend lint and TypeScript/production build passed. Vite retains the existing main-bundle size warning (SQL lazy chunk approximately 491 KB, main bundle approximately 866 KB). git diff --check passed; modified/new source files were also checked independently because Phase 9 files are still untracked.
29. **Manual browser verification.** Real React/FastAPI/PostgreSQL/DuckDB/cumulative Gold fixture in a disposable schema. Orders status + COUNT(*) + SUM(amount), explicit grouping and descending count returned ['open', 2, 30], Current. Confirmed Customers → Orders LEFT count returned 2 while both sources were current. Save/rename/search/history, validation/formatting, CodeMirror/completion, manual-SQL reverse guard, New Query guard, catalog search, keyboard/viewport/Escape and mobile/tablet layouts were verified. Marking only the isolated Orders source stale disabled it and removed the corresponding relationship; the remaining current Customers single-source aggregate still returned ['open', 2, 30]. Public business data was not modified.
30. **Known limitations.** Builder has no general reverse-SQL importer, HAVING, arbitrary/calculated expressions, parent output fields, multiple sorts or multihop joins. SQL Editor supports the existing validated subset. Grouping/filter/selection and chart bounds remain intentional. Category values are not enumerated. No semantic KPI inference. History is metadata only. Builder state is a live session; recovery storage retains scoped SQL text only, never result rows. The public API was not running, so no production restart/deployment was performed in this UI task; verification used the dedicated project API fixture. A formal assistive-technology audit was not performed.
31. **Approval readiness.** Ready for UI review/approval with the documented V1 boundaries. No commit, no new migration, no Phase 10 work, and no weakening of SQL validation, DuckDB sandboxing, ownership/isolation, freshness, relationship/fanout, sensitivity, read-only or resource-limit rules.
