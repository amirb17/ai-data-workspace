# Phase 8C — Workspace Analytics Experience

1. **Existing workspace analytics UX discovered.** Evolved the existing `/app/workspaces/:workspaceId/analytics` surface. It already had authoritative Phase 8A metric execution/results and Phase 8B Ask planning, persistence, history and follow-ups. The previous UI listed all metrics equally, placed Ask first, used three operational counters, and rendered grouped metric results mostly as tables. Existing Overview, Understanding, Metrics, Data Model, Processing and Data Quality remain the deeper workflows.

2. **Files changed.** Backend: `app/services/workspace_analytics_service.py`, `app/processing/workspace_question_resolution.py`. Frontend: `frontend/src/features/workspaces/analytics/{presentation.ts,ResultVisualization.tsx,WorkspaceMetricCard.tsx}`, `frontend/src/features/workspaces/ask/{WorkspaceAsk.tsx,AnswerCard.tsx}`, `frontend/src/pages/Workspace/Analytics/WorkspaceAnalyticsPage.tsx`, `frontend/src/pages/Workspace/WorkspaceDetailPage.tsx`, `frontend/src/services/api/{workspaceAnalytics.ts,workspaceQuestions.ts}`. Validation: `tests/test_workspace_analytics_experience.py`, `frontend/tests/{analytics-experience.cjs,phase8c-fixture-display.cjs,phase8a-fixture-display.cjs}`, `tools/{phase8c_fixture.py,phase8c_readonly_check.py}`. Evidence: this report, `docs/phase8c-*.json`, `docs/phase8c-*-results.xml`, final screenshots under `screenshots/phase8c/`. Pre-existing untracked Phase 8A/8B tests and tools are preserved. Generated Phase 8A HTML is restored and temporary preview HTML removed after verification.

3. **Analytics information architecture.** Header/readiness → compact authoritative summary → key metrics → trends/breakdowns → progressive attention/pending/other metrics → integrated Ask → collapsed recent updates/sources. At most six primary KPIs and four primary charts. No second analytics route or dashboard editor.

4. **Header/readiness behavior.** Workspace name, last calculation time and one Refresh Analytics action. Eight backend presentation states map to human wording: no trusted data, setup in progress, some analytics available, refresh required, refreshing, current, needs attention, failed. Existing machine statuses remain API facts. Busy states announce progress without percentages.

5. **Workspace summary.** Backend supplies trusted datasets, executable available metrics, current metrics, stale/failed/blocked attention count, and current confirmed relationships. Trusted datasets count active datasets with a published current state; this count does not claim their analytics are fresh. Live commerce: six trusted datasets, zero available/current metrics, sixteen needing attention, one confirmed relationship.

6. **KPI selection/presentation.** Only backend FRESH scalar outputs, excluding REVIEW_REQUIRED, qualify. AUTO_ACCEPT sorts first, then semantic confidence, then stable candidate ID. Six-card limit; other current metrics remain expandable. Values lead, timestamps follow, technical details stay secondary. Recommended metrics retain optional review labels.

7. **Metric formatting.** Locale count separators, sensible decimal precision, one decimal for percentages, exact large integer strings, neutral unknown units. Null and empty inputs are distinguished from actual numeric zero. The current metric contract has no authoritative currency code, so no currency symbol is inferred.

8. **Trend/comparison behavior.** No KPI trend arrows or invented prior-period comparisons. Backend-supported Ask comparisons keep explicit period bounds, values and deterministic percentage change, including unavailable/zero-baseline behavior. No claim that an increase is good or a decrease is bad.

9. **Grouped chart behavior.** One categorical dimension uses a bar chart, including a legitimate one-category result. Up to twelve supplied categories are plotted. Exact supplied values remain in a scoped-header table; category omissions and backend truncation are disclosed. Multi-dimension, null-valued and exact-large-integer results use the table fallback.

10. **Time-series behavior.** Validated explicit DAY/WEEK/MONTH/QUARTER/YEAR grain produces chronological lines. Missing calendar buckets insert a null gap, never zero or an interpolated value. Invalid time labels, insufficient buckets or unsupported shapes fall back to exact tables. Large series above the bounded display threshold use tables.

11. **Chart selection/safety.** Shared deterministic mapping: scalar KPI, categorical bar, explicit time line, ranking horizontal bar, supported comparison display, otherwise table. Numeric axes include zero for positive and negative results. No 3D, arbitrary AI configuration, guessed currency, stale plots or fabricated missing observations. A real resize defect was fixed: a hidden Recharts tooltip retained its desktop offset and expanded mobile scroll width to 582px; chart containment now keeps the 390px viewport's content width at 375px.

12. **Ask Your Workspace integration.** Ask lives directly after the analytical content, with the grounded placeholder, labeled textarea and visible submit action. Three recent answers appear initially; earlier owned answers are expandable. New analysis resets context and returns focus to the input. Clarification, unsupported, refresh-required and failure behavior remains authoritative.

13. **Suggested questions.** Show at most four backend-approved current executable suggestions. Frontend invents none. Commerce has none while trusted measures are unavailable. Existing follow-up eligibility continues to come from backend validation.

14. **Ask answer presentation.** Shared value formatting and charts/tables match metric cards. Scalar answers remain numeric, grouped answers show charts with exact tables, explicit time grains show lines, and valid comparisons retain period/value displays. Stale answers display historical refresh guidance and withhold current values/charts.

15. **Provenance/details.** Native expandable How this was calculated contains interpretation, explanation, freshness, timestamp and named sources. Named relationship versions are resolved from current confirmed references. Internal source/version IDs are nested secondary details; storage paths, credentials and hashes are not shown.

16. **Metric detail/review behavior.** Keyboard-operable native details show description, bounded formula, named datasets, dimensions, freshness, calculation time and relationship provenance. AUTO_ACCEPT has no review action. REVIEW_RECOMMENDED review remains optional. REVIEW_REQUIRED is withheld from primary KPIs and shows a definition action. Native disclosure avoids modal focus traps.

17. **Refresh/stale behavior.** Existing refresh/retry endpoints, persistence and idempotency remain. Read polling is fifteen seconds, without scheduled or automatic recalculation. Stale backend outputs are absent and frontend also withholds stale cards/answers. Source refresh is explained separately from retrying a calculation. Network failures clear cached displayed results and offer recovery.

18. **Partial-success behavior.** Current successful values remain usable alongside explicit stale, retry and definition counts. The isolated failure fixture preserves count = 2 while sum fails, then recovers sum = 30. Corrected the initial partial notice so failed metrics count as needing retry instead of disappearing from the notice.

19. **Needs-attention behavior.** A separate progressive section appears for stale, failed or blocked results. Failure cards explain retry; stale cards point to sources; blocked cards show backend definition/relationship guidance. Initially four attention cards, with the rest expandable. No forced review dialog before using current analytics.

20. **Data quality/recent update behavior.** Link to the existing Data Quality surface; no unsupported issue count or quality score. Backend returns at most three latest owned published source updates, with dataset/file name, timestamp and authoritative inserted/updated counts. Upload IDs are absent from the primary presentation. Fixture reports two inserted records.

21. **Empty/loading/error states.** No-data guidance links to Datasets. Not-ready guidance links to Metrics and uses the existing refresh eligibility. Loading skeletons contain no placeholder zeros and honor reduced motion. Calculation errors use safe text/retry; no tracebacks. Zero, unavailable value and no matching inputs have distinct presentation. No empty chart shells.

22. **Navigation/routing.** Stable direct analytics route remains. Breadcrumb uses Workspaces → real workspace name → Analytics. Existing workspace tabs stay coherent; no new redundant route. Actual commerce deep link was checked after project API startup.

23. **Workspace isolation.** Keyed analytics and Ask scopes remount before a new workspace loads. Abort controllers and revision guards reject late responses. Question text, context, metrics, history, readiness and errors do not carry over. Browser switch to a second owned empty fixture showed no previous KPIs or answers; returning restored only Orders' server-owned history with reset context.

24. **Accessibility.** Form labels, status/alert announcements, minimum-height actions, visible focus, native keyboard disclosures, chart text descriptions and captioned tables with scoped headers. Recharts accessibilityLayer enabled and ArrowRight verified to expose open/value 2. Keyboard submitted the natural question and expanded calculation/table/metric details; New analysis returned focus to the textarea. No new dialog.

25. **Responsive/mobile behavior.** Primary metric/chart grids adapt across desktop, tablet and single-column mobile. Tested 1280px desktop, 768px tablet and 390px mobile. Input, submit, cards, disclosures and chart/table fit. Mobile document width measured 375px with a 390px viewport after fixing tooltip overflow; no horizontal page scrolling. Temporary viewport override reset after verification.

26. **Performance/API coordination.** Reuse existing analytics/readiness/history APIs and chart dependency. Analytics source context is gathered once per read rather than twice. Additive summary and a three-row recent-update query are returned with analytics. Fifteen-second reads, serialized actions, bounded primary cards/charts/categories and collapsed history reduce churn. Backend remains authoritative for all execution, validation, eligibility and freshness.

27. **Security/privacy.** Existing ownership, typed planning, metric/relationship validation, freshness and fanout gates preserved. No SQL feature, raw-row browsing, secrets, storage paths, unrestricted joins or new dependencies. Public live checks are read-only. Dedicated fixtures use disposable PostgreSQL schemas, current synthetic Gold and typed synthetic planner responses; no live Gemini call or invented public metric approval. Verified public core counts and 39 prior answer rows unchanged.

Existing answer tests cover clarification, unsupported, comparison and provenance. Browser evidence supplies keyboard, focus, deep-link, responsive and workspace-switch checks.
